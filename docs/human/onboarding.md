## 2. First-Time Setup

### 2.1 Clone Repo

```bash
git clone <repo-url>
cd <repo-folder>
```

### 2.2 Run Initialization Script

If you're the **first developer** setting up this project from the template:

```bash
python scripts/init_project.py
```

This will:
1. Prompt for project metadata (slug, display name, Azure AD IDs, etc.)
2. Generate `project.config` (single source of truth)
3. Update `backend/pyproject.toml` + `frontend/package.json` with project name
4. Generate `backend/.env` and `frontend/.env` from your inputs
5. Generate `README.md` from template
6. Update `.gitignore`

**If `project.config` already exists** (you're joining an existing project), skip to step 2.3.

### 2.3 Fill in Secrets

After init, fill in these in `backend/.env` (gitignored, never commit):

```bash
# From Azure Portal → App registrations → Certificates & secrets
AZURE_AD_CLIENT_SECRET=

# From https://console.anthropic.com/
CLAUDE_API_KEY=

# Set a strong dev password (any value)
DB_PASSWORD=
```

### 2.4 รัน Local Dev

Local dev: **DB + backend รันใน Docker** (Compose project เดียว `srm_fieldinspect`) **· frontend รันบนเครื่อง** (Vite hot reload, :5173)

**เปิดทั้งหมดด้วยคำสั่งเดียว:**

```bash
start-service.bat
```

Canonical Compose command ที่ `start-service.bat` เรียกใช้ภายใน (เทียบเท่ากัน):

```bash
docker compose --env-file backend/.env -p srm_fieldinspect -f docker-compose.yml -f docker-compose.dev.yml up -d db backend
```

**First-time เท่านั้น** — seed ข้อมูลเริ่มต้น (ถ้า DB ใหม่ยังไม่มี super admin):

```bash
docker compose --env-file backend/.env -p srm_fieldinspect -f docker-compose.yml -f docker-compose.dev.yml exec backend python -m app.db.seed
```

> `setup.bat` ทำให้อัตโนมัติตอนสร้าง project ครั้งแรก. ดู [`docs/deployment.md`](../deployment.md) §4 เป็น source of truth ของ local runtime

### 2.5 Verify

- Backend health: <http://localhost:8000/health>
- API docs: <http://localhost:8000/docs>
- Frontend: <http://localhost:5173>

## 3. Local Development Workflow

### 3.1 Common Commands

```bash
# Backend (รันบนเครื่อง)
cd backend
pytest                                        # run tests
pytest -m unit                                # unit tests only
ruff check . && black --check . && mypy app   # lint
alembic revision --autogenerate -m "msg"      # new migration
alembic upgrade head                          # apply migrations

# Frontend (รันบนเครื่อง)
cd frontend
npm run lint
npm run typecheck
npm run test
npm run build

# DB + backend (Docker, project เดียว srm_fieldinspect)
docker compose --env-file backend/.env -p srm_fieldinspect -f docker-compose.yml -f docker-compose.dev.yml logs -f backend db   # tail logs
docker exec -it srm-fieldinspect-db psql -U srm_fieldinspect -d srm_fieldinspect                                                # psql shell
```

⚠️ **ห้ามรัน `docker compose down -v`** — จะลบ volume `srm-fieldinspect-db-data` และข้อมูลหายถาวร ต้องการ DB สะอาดดู §6.7

> backend / frontend รันบนเครื่อง — log อยู่ใน terminal ที่รัน ไม่ต้อง `docker compose logs`

## 5. Azure AD Setup (One-Time, per Tenant)

ถ้า project รองรับ internal users (`AUTH_SCOPE` = `both` หรือ `internal_only`):

1. Azure Portal → Microsoft Entra ID → App registrations → **New registration**
2. Name: `<Project Display Name>` (จาก `project.config`)
3. Supported account types: **Single tenant**
4. Redirect URI: **Single-page application (SPA)** → `http://localhost:5173/auth/callback`
5. After creation, copy:
   - **Application (client) ID** → `AZURE_AD_CLIENT_ID`
   - **Directory (tenant) ID** → `AZURE_AD_TENANT_ID`
6. Certificates & secrets → **New client secret** → copy value → `AZURE_AD_CLIENT_SECRET`
7. API permissions → Add: `openid`, `profile`, `email`, `User.Read`
8. Grant admin consent

Repeat for staging/production with separate redirect URIs.

## 6. Troubleshooting

### 6.1 `docker compose up` fails on port conflict

```bash
# Find what's using port 5432/8000/5173
lsof -i :5432    # macOS/Linux
netstat -ano | findstr :5432   # Windows
```

Change host port in `docker-compose.yml`:
```yaml
ports:
  - "5433:5432"   # changed from 5432:5432
```

### 6.2 `alembic upgrade head` fails with extension error

```bash
docker compose exec db psql -U $DB_USER -d $DB_NAME -c \
  'CREATE EXTENSION IF NOT EXISTS "uuid-ossp"; CREATE EXTENSION IF NOT EXISTS "pgcrypto"; CREATE EXTENSION IF NOT EXISTS "pg_trgm";'
```

ถ้าต้องการ pgvector (AI embeddings): เปลี่ยน image เป็น `pgvector/pgvector:pg16` แล้วรัน `CREATE EXTENSION IF NOT EXISTS "vector";`

### 6.3 Azure AD login: `AADSTS50011 redirect URI mismatch`

Add `http://localhost:5173/auth/callback` to App Registration → Authentication → Redirect URIs (type: SPA).

### 6.4 Frontend `EADDRINUSE :::5173`

```bash
# Kill stale Vite process
pkill -f vite     # macOS/Linux
taskkill /F /IM node.exe   # Windows
```

### 6.5 Backend `ModuleNotFoundError: No module named 'app'`

```bash
cd backend
pip install -e .
```

### 6.6 `Permission denied` on `init_project.py` (macOS/Linux)

```bash
chmod +x scripts/init_project.py
```

### 6.7 Reset DB completely

⚠️ Volume `srm-fieldinspect-db-data` เป็น `external` โดยตั้งใจ — **ห้าม
`docker compose down -v` และห้ามลบ volume นี้ด้วยมือ** ป้องกันการลบข้อมูล local
โดยไม่ตั้งใจ

ต้องการ DB สะอาดจริง ๆ (เช่น ข้อมูลเสียหาย):

1. **Backup ก่อนเสมอ** — `pg_dump -Fc` ผ่าน `docker exec srm-fieldinspect-db`
   แล้ว `docker cp` ออกมาเก็บนอก repo (ดู [`docs/deployment.md`](../deployment.md))
2. หยุด stack: `stop-service.bat`
3. **Restore จาก backup** (ไม่ใช่สร้าง DB ว่างใหม่) — คืนค่า volume เดิม
4. Alembic/seed จะ idempotent อยู่แล้ว ไม่ต้องรันซ้ำเว้นแต่ restore เป็น DB เก่ากว่า head

หากต้องการ DB ว่างเปล่าจริง ๆ (dev เครื่องใหม่ที่ไม่มีข้อมูลสำคัญ) ให้ปรึกษาทีมก่อน
ลบ volume ด้วยมือ — ไม่มี one-liner ที่ปลอดภัยสำหรับกรณีนี้ในเอกสารนี้โดยเจตนา

## 8. Branching & Commits

### 8.1 Branch Naming

| Type | Pattern | Example |
|---|---|---|
| Feature | `feat/<short-description>` | `feat/add-product-search` |
| Bug fix | `fix/<short-description>` | `fix/login-redirect-loop` |
| Chore | `chore/<short-description>` | `chore/upgrade-fastapi` |
| Hotfix | `hotfix/<short-description>` | `hotfix/critical-auth-bypass` |

### 8.2 Commit Messages (Conventional Commits)

```
<type>(<scope>): <subject>

[optional body]

[optional footer]
```

Types: `feat`, `fix`, `chore`, `docs`, `style`, `refactor`, `test`, `perf`

Examples:
```
feat(products): add full-text search via pg_trgm
fix(auth): correct JWT expiry calculation in refresh flow
chore(deps): bump fastapi from 0.110.0 to 0.111.0
```

### 8.3 PR Process

1. Create branch from `main`
2. Make changes + tests
3. Push, open PR
4. CI must pass (lint + tests + coverage)
5. Get 1 approval
6. Squash-merge to `main`

## 12. Dev / Prod parity

Daily dev ใช้ "fast mode" (DB Docker + B/F native) เพื่อ HMR เร็ว — แต่ปัญหาที่เคยเจอตอน deploy (Dockerfile rot, env var ไม่ load, container crash) จะถูกจับ 2 ชั้น:

1. **CI: `docker-smoke` job** — รันทุก PR; build `backend/Dockerfile` + `frontend/Dockerfile`, boot full stack (backend + frontend + Postgres), ping `/health` ทั้ง 2 services ก่อน merge เข้า main
2. **Local: `scripts/smoke-prod.{sh,bat}`** — เรียกก่อน push ใหญ่ หรือเมื่อ AI assistant สงสัยว่าเป็น Docker/env bug; ใช้ `docker-compose.smoke.yml` เดียวกับ CI

→ **ไม่ต้องลง Postgres native, ไม่ต้อง switch compose file ทุกวัน** — แต่ pre-deploy bug ถูกจับเหมือนกัน

ถ้า smoke fail บน local แต่ผ่าน fast mode → 99% เป็น Docker/env issue — ดู log ที่ `docker compose -f docker-compose.smoke.yml logs`
